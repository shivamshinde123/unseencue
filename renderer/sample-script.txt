# My AI Agent Workflow
Hi! In this video I'll walk you through how I build software with **AI agents**: how I plan, how I use {#ffd166}agent skills{/}, and how I keep the agent {white|#6b62f2}honest and on track{/}.

## 1 · Plan Before Any Code
Every project starts with a short spec, not a prompt. I write down the *goal*, the *users*, and what "done" looks like.
- {#4cc9f0}Requirements first{/}: the agent asks questions before building.
- {#90be6d}Docs as memory{/}: decisions go in a `docs/` folder so the next session picks up cold.
- **One task at a time**, each with a clear finish line.

> {black|#ffd166}SHOW:{/} The docs folder and the decision log.

---

## 2 · Agent Skills Do the Heavy Lifting
A **skill** is a packaged playbook the agent loads when a task matches: design rules, a review checklist, a deploy routine.

### The skills I use most
1. **Design system** · keeps every screen consistent.
2. **Code review** · catches bugs before I do.
3. **Browser testing** · clicks through the app like a real user.

> {white|#ff4d6d}SAY:{/} Skills turn "be careful" into a repeatable process.

---

## 3 · Verify, Don't Trust
I never accept "it works" without proof. The agent runs the tests, takes screenshots, and shows me what it checked.

| Step | Tool | Proof |
|------|------|-------|
| Unit tests | Node test runner | 5 of 5 passing |
| UI walk-through | Automated clicks | 35 screenshots |
| Capture check | Screen capture API | Window hidden |

### Why it matters
Agents are fast, but **speed without checks** just ships bugs faster. Verification is what makes them {#90be6d}trustworthy{/}.

> {black|#90be6d}PAUSE:{/} Two-second beat, then wrap up.

---

# Wrapping Up
That's my workflow: **plan**, **use skills**, **verify everything**. Thanks for watching!
